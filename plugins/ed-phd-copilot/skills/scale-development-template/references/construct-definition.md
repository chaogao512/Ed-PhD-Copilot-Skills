# Construct Definition for EdTech Governance Scales

The construct definition is the foundation of instrument quality. A vague construct produces a vague scale that no validation can rescue.

## 1. Definition requirements

A usable construct definition must answer:

1. **Name and label**: the construct's name and any competing labels in the field (e.g., 教师数字素养 vs 教师数字胜任力 — state which you adopt and why).
2. **Domain**: the setting and population the construct applies to (e.g., 高校教育数据治理能力, population = 高校信息化管理部门).
3. **Conceptual boundary**: what the construct includes and explicitly excludes (e.g., 数字胜任力不包括基础软件操作熟练度，如果文献不支持).
4. **Theoretical anchor**: the theory or prior framework the construct derives from (e.g., TPACK, DigCompEdu, UNESCO 教师数字素养框架, 协同治理理论).
5. **Level of analysis**: individual, group/unit, or organization — the scale items must match that level.
6. **Temporal nature**: state (current) vs trait (stable) vs process (change) — this decides retest expectations.

## 2. Dimension derivation

| Derivation source | Use when | Output |
|---|---|---|
| Theory/framework decomposition | A framework defines dimensions (e.g., DigCompEdu 6 areas) | Map each framework dimension to a scale dimension with a definition |
| Literature synthesis | Multiple studies use overlapping sub-constructs | Extract candidate dimensions; merge duplicates; justify exclusions |
| Qualitative exploration | Construct is new in the governance context | Run interviews/document analysis first; derive dimensions from coded themes |
| Expert panel | Practice knowledge is required | Delphi-style rounds to confirm dimensions and boundaries |

Requirements: (a) each dimension must have a one-sentence definition; (b) dimensions must be mutually exclusive (items must be assignable to exactly one dimension); (c) the dimension set must cover the construct domain (no missing core facet); (d) record the derivation evidence for every dimension.

## 4. Operationalization rules

- Every dimension needs at least two observable behavior indicators before items are written.
- Distinguish the construct from its causes and consequences: an item measuring "领导支持" does not measure "数据治理能力" unless the theory defines it as part of the construct.
- For self-report scales, state what respondents can actually know (e.g., teachers can report perceived support; they cannot reliably report their own competence — use performance-based or mixed formats where the claim demands it).
- Record all definition decisions in the instrument log so the validation section can refer back to them.

## 5. Failure signals

- Construct defined only as "the ability to use technology well".
- Dimensions borrowed from a framework but relabeled without justification.
- Items mixing the construct with its outcomes (e.g., competence items that ask about student achievement).
- No evidence trail connecting the construct definition to theory or prior instruments.
