# 3.1 完成一篇科研论文，你需要做几件事情（教育技术版）

> 本文改编自 [Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) (CC BY-NC-SA 4.0)，内容已针对教育技术专业博士研究场景进行迁移适配。

大体来说，写论文的过程不仅是语言表述的工作，更多的是构建清晰的逻辑框架和表达有力的研究思路。下笔写之前，你需要想明白以下几个重要问题。注意，下面不是论文 Introduction 的写作逻辑，而是一些 checklist，帮助你去思考这个 Idea 和 Solution 是否值得探索。

## 1. Background, Why & Problem: 你这篇论文要干啥？为啥值得干这件事？

a. **现状背景**：首先要交代一下你研究的领域是什么【即开章明义，点名你是做哪个（小）领域的研究】。这个领域现有的代表性工作都做了些什么？这些研究中有什么共性和不足之处？

b. **现有方法的局限性**：你所选择的研究领域中，现有方法存在哪些局限性？是某些教育问题没有被完全解决？还是现有方案不能应对一些特定的教学场景（如大班额、混合能力课堂、资源匮乏地区）？指出这些局限性，才能佐证你这篇论文的 Motivation、意义和价值。

c. **明确问题**：明确指出你论文所要解决的核心问题。一般来说，你可以在引言的这一部分清晰地写出："Our goal is to..."/ "We study the problem of ..."，直接阐述你研究的目标/问题。进一步刻画该问题的本质属性与硬约束（教育情境约束：学段、学科、课时、班级规模、技术可达性、伦理边界等），从而自然导出本文要解决的研究目标或问题定义（Our Goal / Problem Formulation）。

d. **Why: 为什么这个问题值得研究？**：详细阐述为何这个问题值得研究，解决该问题能够带来什么样的学术价值或实际应用价值。【注意，部分要和后面的 How 和 So what 做一个对应】，即你这里埋下了论文的 motivation，后面的方法和贡献，要很好地解决和回应这个 motivation。

### 用 Running Example 让 Motivation"活"起来

在阐述 Why 时，强烈建议引入一个 **Running Example**（贯穿全文的运行例子）。这是让你的论文从"干巴巴的技术报告"升级为"有说服力的学术叙事"的关键手段。

**什么是 Running Example？** 它是一个贯穿论文始终的、具体的、真实的教学场景。你在 Introduction 中用它来引出问题，在 Problem Formulation 中用它来解释定义，在 Methodology 中用它来展示你的方法如何一步步工作，在 Experiments 中用它来做 Case Study。它是你整篇论文的"锚点"。

**为什么需要 Running Example？** 审稿人每天要审大量论文，他们没有耐心从头到尾仔细阅读你的每一段文字。一个好的 Running Example 能让审稿人在 30 秒内"get 到"你的问题是什么、为什么难、你的方法为什么巧妙。抽象的描述（如"智能导学系统的冷启动问题很严重"）远不如一个具体的失败案例来得有冲击力。

**怎么设计 Running Example？** 最经典的结构是"真实场景 + 失败案例"的组合。

> 例如：假设你研究的是智能导学系统中的学习者建模冷启动问题。不要只说"新学生没有历史数据，推荐不准确"，而是给出一个具体的例子：一名刚入学的高一新生小明，没有任何历史学习行为数据。传统协同过滤方法无法为他推荐任何学习内容（因为他与任何已有学习者都没有相似度），系统只能退回随机推荐，导致小明第一次使用就遇到了远超其水平的微积分题目，产生挫败感而放弃使用。而如果引入知识图谱中该生入学测验的先验知识（其代数基础薄弱、几何基础良好），系统就能给出合理的初始推荐。这个具体的失败案例，比任何抽象的描述都更能让审稿人理解你的问题的迫切性。

**Running Example 的设计原则**：
- 真实且具体：来源于真实课堂或真实数据，不要编造
- 简洁但完整：足够简单以便读者快速理解，但又包含足够的复杂性来展示问题的难度
- 贯穿全文：在 Introduction、Methodology、Experiments 中反复出现，形成叙事闭环

## 2. What: 为啥别人干不了，你能干？有啥研究挑战？核心思想是啥？

a. **研究挑战**：要讲清楚，你做这个具体研究问题是什么？例如你是针对智能导学系统不能为新生提供个性化学习路径的问题展开研究，你要提一个融合先验知识的学习者建模方案，这里面的研究挑战是啥？为啥别人干不了？教育技术领域的挑战通常不是"搜索空间爆炸"这类系统约束，而是：

- **学习者行为数据的稀疏性与异构性**：真实课堂中学生行为数据稀疏、模态异构（日志、问卷、访谈、成绩单），简单套用现成算法难以奏效；
- **教育干预的因果推断困难**：学校场景往往无法随机分配学生到干预组和对照组，混杂因素（教师差异、家庭背景、成熟效应）众多，直接套用 naive 的前后测对比会得出误导性结论；
- **技术方案与课堂教学节奏的适配**：技术方案设计得再精巧，如果与 45 分钟课堂节奏、教师工作流、学校管理制度冲突，就无法落地，而"无法落地的教育技术"在审稿人眼里价值大打折扣。

研究挑战通常不超过 3 点，并且要解释为何直接套用或简单扩展已有方法难以奏效。

b. **核心思想**：在面对这些挑战时，你提出了什么新的思路或方法？这些思路和方法是受什么启发的？这部分你要用大白话介绍，让读者能 get 到你的含义。例如，Inspired by... Observation(可选), we propose ...

## 3. How: 你是怎么干的？

a. **方法概述**：简要描述你的方法框架（干预设计/系统架构/分析模型），给出一个高层次的概览。

b. **方法细节**：详细描述你方法/干预的每一个关键组件和步骤（对应教育研究中的"干预方案"或"研究设计"，并说明其理论依据）。

c. **贡献总结**：在 Introduction 的最后，用一个清晰的列表总结你的贡献点（通常 3-4 点）。教育技术论文的贡献点必须至少包含一项"对教与学意味着什么"（理论贡献、实证证据、设计原则、工具/数据、实践启示五类中的若干）。

## 4. So What: 你干了那么多，又怎么样？

a. **实验设计的闭环验证**

b. **主实验（Main Results）**：教育研究中，主实验是"与对照条件/最优可用干预的对比"（常规教学、候补干预、安慰剂对照），报告效应量（Cohen's d、η²）+ 置信区间，而非简单的"提升几个百分点"。

c. **干预效果的多维度验证**：教育干预的效果验证是多维度的，除了学习效果（学业成就、学习增益），还应考虑学习体验（投入度、动机、自我效能）、教师接受度（可用性、工作流适配）、组织可行性（成本、可扩展性）。如果提出了两个核心技术点（如一个诊断模块和一个个性化推荐模块），需要通过设计分析（析因设计、调节与中介分析、轮次对比）逐一检验其独立贡献。

d. **深度分析（In-depth Analysis）**：除了主指标，还需要根据问题的硬约束补充多维度分析。这部分的实验设计必须与你在 Background/Why 中提出的 Motivation 直接对应：

- **Case Study**：回到你在 Introduction 中引入的 Running Example，展示你的方法在这个具体例子上的完整工作过程和最终结果。这不仅是对全文叙事的完美收束，也是最能让审稿人"眼前一亮"的部分。教育研究中，质性个案证据（学生访谈、课堂观察）往往是 DBR 与系统论文的加分项。
- 实验不仅要展示"效果好"，更要通过数据解释"为什么好"（Provide insights）。每一个实验结果后面，都应该有 1-2 句分析，解释造成效果差异的原因（机制层面，可引用学习理论）。

---

> 建议先将前述要点整理为可讨论的叙事提纲，并与导师沟通是否需要调整论文叙事框架；框架相对稳定后再撰写正文。实践中可先完成主要插图（尤其是 Motivated Example、Solution Overview），再撰写对应章节文字：前者有助于反复校验 Introduction 的叙事与术语一致性，后者有助于厘清 Methodology 的结构安排。
