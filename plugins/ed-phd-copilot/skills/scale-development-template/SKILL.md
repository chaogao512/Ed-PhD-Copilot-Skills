# Scale Development Template

## Overview

Design a defensible measurement instrument (量表/测评工具) for education technology and governance constructs such as digital competence, data governance capability, human-AI collaboration readiness or perceived algorithmic fairness. Replace "we designed a questionnaire" with a documented chain: construct definition → dimension derivation → item pool → expert review → pilot → EFA → CFA → reliability/validity evidence → norms or cut-off points. Every stage must be reported so reviewers can audit instrument quality.

## Required Inputs

Ask for missing items: the construct name and theoretical anchor, the intended population and use context (e.g., 中小学教师/高校管理者), the decision the scale will inform (research vs evaluation vs screening), and the target validation standard (CSSCI manuscript, SSCI manuscript, doctoral chapter).

## Core Procedure

1. Define the construct: name, domain, conceptual boundary, dimensions, and relationship to the theoretical anchor.
2. Derive dimensions and draft a construct definition table (dimension → definition → behavior indicators).
3. Develop the item pool: ≥2–3 items per dimension, review against item-writing rules.
4. Run expert review (content validity): experts, criteria, revision decisions, I-CVI/S-CVI reporting.
5. Pilot test with a representative small sample; check item statistics and clarity.
6. Collect the validation sample; run EFA to explore structure, then CFA to confirm it.
7. Report reliability (α / McDonald's ω / test-retest) and validity evidence (content, construct, convergent/discriminant, criterion).
8. If the instrument supports decisions, develop norms or cut-off points with explicit evidence and caveats.

## Quality Rules

- Never claim a scale is "validated" from EFA alone; CFA or a confirmatory cross-sample step is required for that claim.
- Never report Cronbach's α without stating the sample, item count and dimension structure.
- Report the full item list, response format and scoring rules so the instrument is reproducible.
- If the instrument is used for high-stakes evaluation, add measurement invariance and fairness checks across relevant groups.
- Route instrument-only studies back to `mixed-methods-evidence-template` when the research question needs triangulation with other evidence types.

## Output Format

1. Construct definition table
2. Dimension and item pool summary
3. Expert review plan and content validity results
4. Pilot and validation sampling plan
5. EFA/CFA analysis plan with pre-specified criteria
6. Reliability and validity evidence checklist
7. Norms/cut-off decision (or explicit statement that they are out of scope)
8. Remaining validation gaps and next steps
