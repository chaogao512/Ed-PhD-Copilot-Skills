# Case: 基于学习分析的大学生学业预警与精准支持机制研究

## Case Purpose

本案例用于测试技能链能否处理学习分析、学业预警、算法公平和学生数据权益类主题。重点检验技能是否会把"预警系统"误写成纯技术系统、是否会把标签化推送等同于教育支持、以及是否会在预警算法影响学生学业决策时保持伦理与问责边界。

## Research Background

高校普遍部署学习管理系统（LMS）、智慧教室和校园数据平台，积累了学生出勤、作业、测验、在线学习行为等伴随式数据。学业预警（early warning）通过算法识别学业风险学生并触发支持。实践中常见问题：预警以行为代理指标（登录次数、视频时长）代替真实学业表现；预警结果被直接用于谈话、劝诫甚至处分；学生不知道自己被预警、不知道数据来源、没有申诉渠道；预警与支持资源脱节，只"报警"不"支援"。因此研究的关键不是提高预测准确率，而是构建"预测—解释—支持—反馈"的治理化预警机制。

## Core Governance Problem

如何构建基于学习分析的大学生学业预警与精准支持机制，使预警算法在准确性之外，同时满足解释性、公平性、学生知情权、人工复核和申诉纠错要求，并真正转化为分层精准的学生支持行动。

## Stakeholders

- 学生：数据主体与支持对象，需知情、解释、纠错与申诉权利。
- 学业导师/辅导员：预警信息的使用者，负责人工复核与支持行动。
- 教务与学工部门：确定预警阈值、支持路径与责任分工。
- 信息化/数据分析部门：负责特征构建、模型开发、日志留存与公平性监测。
- 数据治理与伦理委员会：审查高风险预警使用，防止标签固化与歧视。
- 院系管理者：提供学业支持资源（辅导、咨询、学业指导）。

## Initial Research Questions

1. 学业预警机制中，哪些预警信息特征影响辅导员对学生风险的判断与支持决策？
2. 现有预警系统在解释性、公平性和学生知情权方面存在哪些治理缺口？
3. 如何设计"预测—解释—人工复核—分层支持—申诉纠错"的治理化预警机制？
4. 该机制对学生感知的公平性、求助意愿和支持有效性有何影响（在证据边界内）？

## Candidate Theory Anchors

- 学习分析伦理框架：界定知情同意、透明度、人工复核与问责（对应 `theory-anchors.md` 的 Learning analytics ethics frameworks 锚点）。
- 组织支持理论/学生支持理论：把预警从"标记学生"转为"配置支持"。
- 人机协同决策：界定算法建议与辅导员最终判断的权责。
- 形成性反馈理论：预警信息应支持改进，而非贴标签（标签固化是伦理红线）。

## Evidence Route

- 问卷：学生感知公平性、知情度、求助意愿（量表开发可路由至 `scale-development-template`）。
- 访谈：辅导员预警使用体验、学生被预警经历（编码流程使用 `qualitative-coding-guide.md`）。
- 系统日志分析：预警触发率、复核率、申诉率、支持行动完成率（注意行为代理指标边界）。
- 案例比较：不同预警策略院系的机制差异。
- 三角互证：量化结果与质性解释互证，明确预警效果不能仅凭准确率声称。

## Ethics and Data Governance

- 预警算法不得直接触发处分、劝退等惩罚性决策；高影响决策必须人工复核并留痕。
- 学生必须知晓数据来源、预警标准、影响范围，并有解释、纠错和申诉渠道。
- 不得以单一行为代理指标（如登录次数）定义学业风险；特征使用需说明理由并监测公平性。
- 预警标签属于敏感教育信息，访问控制、留存期限与最小化原则必须执行。
- 预警准确率、公平性与支持有效性必须分别报告，不得混用。
