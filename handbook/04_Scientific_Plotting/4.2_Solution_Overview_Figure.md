# 4.2 Solution Overview Figure（解决方案总览图）（教育技术版）

> 本文改编自 [Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills) (CC BY-NC-SA 4.0)，内容已针对教育技术专业博士研究场景进行迁移适配。

## 核心目标

Solution Overview Figure 是论文 Methodology/研究设计章节的"灵魂"。它的使命是让读者（尤其是那些跳过大量文字直接看图的审稿人）迅速掌握你的整体框架、核心模块以及它们之间的数据/信息流转关系。

这张图通常出现在 Methodology 章节的开头（如 Section 3 的第一段之后），是读者理解你整个方案的"地图"。一个好的 Overview Figure 能让读者在阅读后续细节时始终保持全局视角，知道当前讨论的模块在整个系统中的位置。

## 常见的设计范式

### 范式一：Pipeline / 流水线图

这是最常见的范式。适用于你的方案是一个多阶段的处理流程，从左到右（或从上到下）依次展示：输入 → 阶段1 → 阶段2 → ... → 输出。每个阶段用一个大方框表示，大方框内部可以包含子模块的更多细节。

**案例参考**：学习分析论文的典型 Pipeline——"学习分析流程：数据采集（学习管理系统/在线平台日志）→ 特征工程（行为/情感/社交特征）→ 预测建模（如退课预警）→ 可视化仪表盘 → 教学干预"。整个图的逻辑极为顺畅，读者从左到右一看就懂。

### 范式二：系统架构图

适用于你的方案是一个包含多个交互组件的系统。用大方框表示系统边界，内部划分出若干子模块，用箭头表示模块之间的数据流和控制流。

**案例参考**：智能导学系统架构——"学习者接口层 → 教学策略引擎 → 知识图谱层 → 内容推荐引擎 → 学习分析层"，并在图中标注各模块之间的数据流（如学习者行为日志流向学习分析层，分析结果回流到教学策略引擎形成闭环）。教育技术系统架构图务必体现"教学法模块"与"技术模块"的双线结构，并标注理论依据所在模块。

### 范式三：多层次 / 多视角图

适用于你的方案涉及多个抽象层次（如从宏观到微观）或多个视角（如教师端和学生端、离线与在线）。可以使用上下分层或左右分栏来展示不同层次/视角。

**案例参考**：教育信息化治理的多层架构——"基础设施层 → 数据中台层 → 智能服务层（AI Agent 治理）→ 业务应用层"的上下分层图；上下结构一般用于方案由多个层次/阶段组成的情况，左右分栏则常用于输入-处理-输出的线性流程。

### 范式四（教育技术特有）：技术-组织双层拓扑图

教育技术研究（尤其治理与领导方向）常常需要同时呈现**技术系统**与**教育组织**两个层面的交互，这是 CS 论文中不存在的图型。建议采用双层结构：上层展示组织/人员角色（教育行政部门、学校领导、教师、学生、家长），下层展示技术系统模块（数据平台、AI 服务、仪表盘），用纵向箭头表示"技术供给 → 组织采纳/使用 → 反馈迭代"的双向关系。这类图能直观论证"技术方案与学校治理结构适配"这一教育技术论文的核心论点。

## 设计原则

- **模块化**：每个核心组件用一个方框表示，方框内部可以进一步细分。
- **数据流清晰**：用箭头明确标注数据的流向，避免交叉和混乱。
- **层次分明**：通过颜色、大小和位置来区分不同层级的组件。
- **与正文对应**：图中每个模块的名称必须与正文中的章节标题一致。
- **输入输出明确**：最基本的要求是让读者知道方案的【输入】是什么、【输出】是什么，必须在图中清楚表达。
- **体现教育情境**：教育技术论文的框架图应围绕"学习者-教师-系统"的交互关系设计，必要时把理论机制（如认知负荷、自我调节学习）标注在对应模块上。

> **实用建议**：不管用什么工具，画 Overview Figure 之前，强烈建议先在纸上手绘一个草图，与导师讨论确认布局和信息层次后再上机绘制。这能避免大量的返工。也可以参考第五章 Vibe Research，了解如何用 AI 辅助绘图。
